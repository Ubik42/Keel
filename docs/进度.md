## 1. 决定与前提

- 2026-11-21 起，本工程脱离上游 dolag233/Serpent 独立开发，不再合并上游。`upstream` 远端可以保留作参考，不作为合并来源。

- 依赖方向：`@ubik/workbench` 不依赖任何应用；Serpent 与 Panthesia 分别依赖它；Serpent 不依赖 Panthesia。
- 工程计划改名，新名称待定（第 6 节）。MIT 许可允许改名再发布，义务是保留原版权声明与许可全文。

### 3.1 `@ubik/workbench`

**位置与许可。** 先在本仓库 `packages/workbench` 孵化（npm workspaces），便于抽取期间同一提交内同时改包与使用方。第 W 阶段（第 4 节）拆为独立 Git 仓库，Serpent 与 Panthesia 以版本号依赖。许可 MIT，保留来源说明。

**宿主接口（与传输无关）。** 工作台不直接调用后端，只通过宿主注入的接口取数据：

```ts
interface WorkbenchHost {
  storage: KeyValueStorage;            // 偏好持久化；Serpent 用 localStorage 或 IPC，Panthesia 用 localStorage 或 Tauri store
  platform: 'windows' | 'mac' | 'linux';
  labels: WorkbenchLabels;             // 工作台自身的文字，由宿主按语言提供
  icons: IconRenderer;                 // 图标由宿主提供
  clipboard?: ClipboardPort;
}

interface CollectionSource<TItem, TId> {
  total(): number;
  getEntry(index: number): { id: TId; item?: TItem; aspect?: number } | undefined;
  requestRange(start: number, end: number): void;   // 宿主自行决定 IPC 或 invoke
  subscribe(listener: () => void): () => void;
}
```

应用侧的传输模式统一为"一个出口 + 判别联合 + Result + 事件订阅"：

```ts
interface AppTransport<TRequest extends { type: string }, TResult, TEvent> {
  send(request: TRequest): Promise<Result<TResult>>;
  subscribe(listener: (event: TEvent) => void): () => void;
}
```

Serpent 用 `ipcRenderer.invoke` 与 preload 事件实现；Panthesia 用 Tauri `invoke` 与 `listen` 实现。此接口放在工作台的 `host` 模块中作为类型约定，工作台组件不使用它。

验收约束：包内代码与类型不出现 `window.serpent`、`electron`、`@tauri-apps`、Serpent 业务类型（`AssetSummary` 等）、`serpent.` 存储键。用 ESLint `no-restricted-imports` 与一个扫描测试强制执行。

### 3.2 Serpent 渲染层

```
src/renderer/
  app/            启动、Provider、宿主适配（WorkbenchHost、传输）
  stores/         按领域划分的 zustand store
  features/<领域>/ 组件 + 同目录样式 + 领域 hook
```

**store 划分。**

| store | 内容 |

| `navigation` | 范围（全部 / 文件夹 / 标签 / 回收站 / 标签管理 / 插件视图 / 相似）、文件夹与标签数据、递归选项、固定标签 |

| `selection` | 选中资源与文件夹、锚点（基于工作台 selection） |

规则：

- 组件用选择器直接订阅所需切片，不逐层传 props。一个组件的 props 只保留它自身的输入（id、变体），目标 ≤ 10 个。
- 跨领域动作写成具名的协调函数（如 `openLibrary`、`closeLibrary`、`resetLibraryScope`、`applyWorkspaceSnapshot`、`clearFilters`），集中在 `stores/actions/`，替代分散的 setter 序列与 effect 链。
- 后端事件在 `app/` 的单一订阅层处理，分发到 store，不在组件内订阅。
- 镜像 ref 全部改为 `store.getState()`。

### 3.3 样式

- **token 层**：`--ui-*` 为唯一 token 名称空间；旧别名删除。补齐阴影、混色（如 `--ui-wash-hover`）、圆角档位、毛玻璃、动效时长与曲线 token。明暗差异只在 token 中体现。
- **结构层**：每个组件同目录的 `*.css` 只写布局与几何（display、grid、flex、position、尺寸、间距、overflow、z-index 引用）。工作台组件的结构样式随包分发。
- **美术层**：颜色、背景、边框、阴影、圆角、透明度、滤镜、字体只引用 token，不出现字面值。可以与结构层同文件，但分为两个规则块；Stylelint 规则检查美术属性只允许 `var()`。
- **主题**：主题配置只改变 token 值（现状已满足）；删除组件级 `[data-theme]` 覆盖。
- **Islands 与 legacy**：二者是结构变体而非主题。建议保留 Islands、删除 legacy，减少一半变体（待用户确认，第 7 节）。
- `styles.css` 最终删除。

## 4. 阶段

工作量按单人（Agent 连续执行）的工作日估计，含测试与验收。每个阶段完成后提交；跨多天的阶段按子项分批提交，每次提交都满足"通用完成条件"。

**通用完成条件（每次提交）**

1. `npm run typecheck`、`npm run lint` 通过。
2. `npm test` 全部通过；测试文件数与用例数不少于基线。迁入包的测试计入包的测试数；删除或改写的测试在进度记录中逐项说明原因。
3. 涉及交互的改动运行相关 e2e 子集；阶段末运行完整 `npm run test:e2e`。
4. 开发与测试只使用隔离用户数据与临时资源库。真实资源库不打开、不扫描、不迁移。
5. 涉及样式的改动通过视觉基线比对（第 0 阶段建立）。

## 5. 后端与 napi-rs

后端保持 Node。SQLite（better-sqlite3）、全文检索（FTS5 trigram）、向量检索（sqlite-vec）、图像处理（sharp）、PDF 栅格化（@napi-rs/canvas）已经是原生实现；视频与 EXR 走外部 ffmpeg / oiiotool。koffi 只用于系统接口（Job Object、剪贴板、IME、驱动器类型），不在热路径上。

**判断依据（全部满足才引入原生模块）**

1. 现有基准或新增基准显示该环节超出目标（如导入吞吐、首屏时间、交互请求 p95），且 profile 证明耗时在 JS 计算，不在磁盘或网络 I/O。
2. 该环节阻塞 Worker 事件循环，导致交互请求排队（`performance-contract` 的交互通道延迟上升）。
3. 先尝试纯 JS 修复（异步化、流式、分批让出、换用 Node 内建原生能力），仍不达标。
4. 没有成熟的现成原生 npm 包可用。
5. 收益足以抵消成本：三平台预编译、Electron ABI、打包与 `ensure-native` 维护。

**候选环节**

| 环节 | 现状 | 先做的纯 JS 修复 | napi-rs 价值 |
| --- | --- | --- | --- |
| 内容哈希（SHA-256） | `library-service.ts:5800-5830` 用同步 `readSync` + `crypto`，阻塞 Worker | 改为流式异步读取 + `crypto` 增量哈希（`crypto` 本身已是原生） | 低；只有在需要多线程并行哈希大批文件时才考虑 |
| 目录扫描与对账 | JS `readdir` 递归 + `fs.watch`（SMB/NFS 不可靠） | 分批让出、并发限制 | 中；大目录（数十万文件）首次扫描可用 Rust `jwalk` 并行遍历 |
| 调色板提取 | `palette-extractor.ts` 纯 JS 4096 桶直方图 + 聚类，像素由 sharp 解码 | 缩小采样尺寸 | 中低；先用 `test:perf:palette` 测量 |
| 文件头解析 | `image-dimensions`、`raw-image-metadata`、`raw-embedded-thumbnail`、`gif-metadata`、`font-file-metadata` 纯 JS | 只读必要字节 | 低；通常受 I/O 限制 |
| FBX 转换 | ufbx WASM + JS GLB 构建 | — | 低中；WASM 已接近原生，只有大模型批量时考虑 |
| 非 ZIP 压缩包 | `libarchive-wasm`，整包载入内存（有上限） | 流式读取或改由 Worker 处理 | 中；大压缩包内存占用是实际问题时可改原生 libarchive 绑定 |

结论：目前没有候选同时满足 1–5。P7 先用现有基准测量导入、扫描、调色板三项，再按依据逐项决定。

## 6. 改名

- MIT 许可允许改名再发布；必须保留原版权声明（`Copyright (c) 2026 Serpent contributors`）与许可全文，`THIRD_PARTY_NOTICES.md` 继续保留。MIT 不授予名称使用权，独立发布时改名可以避免被认作上游官方版本。

- 新名称确定前，先在 GitHub 与常见应用商店检索同名软件。
