# Keel 新增功能说明

这些是 Keel 在 Serpent 基础上新增或改变的功能。总体介绍见 [README](README.md)，计划与进度见 [docs/进度.md](docs/进度.md)。

## 资源库布局

创建资源库时可以选择素材存放位置：

- **资源库根目录（默认）**：素材直接放在资源库中，保留自己的文件夹结构。外部放入的文件由目录监听或“刷新磁盘变化”加入索引。
- **Assets 子目录**：沿用原版结构，导入的素材存放在 `Assets`。

数据库、缩略图、回收站和操作记录仍存放在 `.keel`。布局保存在 `.keel/storage-layout.json`，版本为 1。没有布局标记的旧库按 `Assets` 模式打开，现有素材和路径保持原样。现有库的布局转换需要单独开发。

## 使用已有文件夹

在“创建资源库”中将“创建方式”设为“使用已有文件夹”，填写显示名称，再点击“选择文件夹并创建”。选中的目录会直接成为资源库，目录中的素材自动加入索引，原文件的位置、内容和目录结构保持原样。显示名称不会重命名所选目录。

此模式使用根目录布局，只在所选目录中创建 `.keel`。已有 `.keel` 时会提示使用“打开已有资源库”，保留原有库数据。数据库初始化失败时，只清理本次创建的元数据。

自动化接口可使用 `library.create({ displayName, selectedParentPath, useExistingFolder: true })`；此时 `selectedParentPath` 指向要原位初始化的目录。可以省略 `storageLayout` 或设为 `root`。

根目录布局由此个人版支持；与原版交换资源库时，使用 Assets 布局。`.keel` 与 `.keelignore` 为保留路径，排除在素材扫描和用户文件操作之外。

## 树形标签与素材联动

左侧常驻“标签”面板，支持搜索、展开折叠、父子标签、新增和重命名。右击标签可新增子标签；拖动标签可调整父子关系，也可通过右键菜单移回根层级。把素材拖到标签上可以批量打标。

点击父标签会显示它及所有后代标签关联的素材，计数按素材去重。子标签与父标签的名字独立保存，名称继续沿用库内唯一规则。删除父标签会保留素材和子标签，子标签移到标签根层级。创建、移动、删除与合并的撤销会保留相关层级关系。

层级保存在数据库的 `tag_hierarchy` 表中，通过第 61 次增量迁移创建。旧标签保持原名和素材关联，并作为根层级标签显示。原有平铺标签管理页继续提供批量选择、合并和删除。

## 标签拖放与外观

把左侧标签拖到图片或其他素材卡片上，只给该素材添加标签（不影响其他选中的素材）。把选中的素材拖到标签上可以批量打标。原有的“素材拖到标签”继续可用。

新建标签自动随机分配颜色和图标。右击左侧标签，指向“图标与颜色”，在标签右侧弹出的面板中选择颜色、Emoji 或图标，选择即生效，也可以随机更换或恢复默认。删除标签的确认同样在标签右侧弹出。外观保存在资源库数据库的 `tag_appearance` 表中（迁移 62），支持撤销和重做。

## 筛选与界面缩放

颜色、形状、尺寸和分辨率筛选集中在过滤栏的“更多”中，已启用条件仍显示为可清除的筛选项。“更多”会在内部条件生效时高亮。过滤按钮图标增加到 18px，点击区域至少 34px。

“设置 → 外观 → 界面缩放”支持 75%–200%，同时调整文字、图标、按钮和间距，立即生效并在重开后恢复。字体大小选项继续独立控制文字。

## Windows 资源库文件夹图标

新建或打开本机可写资源库时，自动把资源管理器中的文件夹图标设为 Keel。图标保存在 `.keel/library.ico`，根目录的隐藏系统文件 `desktop.ini` 使用相对路径引用，资源库移动后仍可使用。

旧 `desktop.ini` 在首次替换时备份到 `.keel/desktop.ini.before-serpent`；其他文件夹显示设置继续保留。旧 Billfish 的 `.bf` 数据保留，并排除在素材索引之外。网络库和只读缓存库跳过图标写入。

## 本机使用

源码目录：`D:\manage\_tools\Keel`。

双击 `Start-Keel.exe` 无控制台启动打包后的程序（命令行入口保留 `Start-Keel.cmd`），或使用桌面的“Keel 开发版”快捷方式。配置单独保存在工程的 `.local-profile`，与已安装的其他版本互不影响。应用没有自动更新。

```powershell
npm ci
npm run rebuild:native
npm run package
```

日常调试可使用 `npm start`；需要独立配置时设置 `KEEL_USER_DATA_PATH` 为绝对路径。

## 验证

新增 `tests/worker/root-library-layout.test.ts`，覆盖默认布局、粘贴文件、保留路径、导入、回收站恢复、忽略、监听、数据库恢复及文件夹/ZIP 导出。

新增 `tests/e2e/root-library-layout.test.ts`，验证中文创建界面、默认选择、可选布局、布局传递，以及根目录外部文件的自动识别。

原版 Worker 测试显式使用 `storageLayout: 'assets'`，保留其原有路径断言。既有库可用性检查继续使用 `npm run test:library-availability`。


## 手机照片固定更新

“手机同步”使用固定根目录资源库。桌面的“更新手机照片”提供增量更新：按设备绑定，跳过未变化文件，以 SHA-256 复用内容，保留历史和改动版本，并保存中断进度。状态在库的 `.keel/phone-sync`，工具源码在 `tools/phone-photo-sync`。

链接文件夹的路径规则支持 `**` 表示全部路径，可先排除全部再包含具体原文件；首次链接即可指定规则。另一 Keel 库的 `.keel`、Billfish `.bf` 及保留元数据文件排除在链接扫描之外。

手机库的工具入口、说明与记录集中在 `_管理`，并排除素材索引。手机的 DCIM、Pictures 等目录直接放在库根目录，更新沿用相同布局。

## 规则

左侧文件夹下方的“规则”列表取代了原来的自动任务。一条规则是资源库 `.keel/rules/<规则 id>/` 下的一份清单 `rule.json` 和一个 TypeScript 脚本，由 AI 编写和修改；目录中自带说明书 `AGENTS.md`、类型声明和示例。

- 触发：导入后、资源库变化后、定时、持续运行或手动。列表的分组与排序即优先级，同一时机按顺序执行。
- 新建或改过的规则需要在桌面确认一次：确认框列出规则的用途、触发方式，以及会修改、会读取的内容。之后按触发方式自动运行。
- 点开规则可以查看触发历史（时间、原因、处理的文件数、改动、日志、错误行号），也可以试运行、立即运行或“复制给 AI”。规则造成的改动可以在撤销菜单中整体撤回。
- MCP 工具和命令行 `Keel.exe --rule list | validate | dry-run | run | history | enable | disable` 提供同样的操作。

合集和智能合集已删除。旧资源库打开时一次性转换：普通合集转为同名标签与成员，智能合集转为暂停的规则；删除转换结果后不会再生成。一次性的自动化脚本仍可从规则列表打开。

## 标签树与侧栏搜索

新建标签直接在树内输入名称；新增子标签会展开父标签，并在父标签下一层显示输入行。重命名保留原位置。Enter 保存，Esc 取消，也可使用输入行右侧的保存和取消按钮。

标签和文件夹的搜索图标与输入框常驻各自标题行。图片右键菜单取消了容易被误认为禁用按钮的“删除”分组标题；使用“移入回收站”或“从硬盘中删除…”执行对应操作。

图片支持双向拖动打标：选中一张或多张图片，拖到标签行上，为这些图片补加标签；把标签拖到图片上，只为落点图片补加标签。Windows 原生文件拖动与内部拖动共用库内资产解析。重复打标不重复关联。固定标签使用图钉图标，固定时高亮。
